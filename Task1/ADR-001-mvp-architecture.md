# Архитектурное решение (ADR)

## Название задачи:
Архитектура распределенной системы мониторинга свиноводческих ферм с гибридной Edge-Cloud моделью

## Контекст и проблема

Компания «АгроТех Х» планирует разработать MVP платформы для мониторинга свиноводческих ферм. Система должна обеспечивать:

- Видеоаналитику для обнаружения драк, задавливания поросят и беспокойного поведения
- Управление кормушками и поилками разных производителей
- Оценку состояния животных по внешнему виду и поведению
- Мониторинг систем фильтрации воды
- Пересчет поголовья и контроль запасов кормов
- Работу в условиях нестабильного интернета
- Высокую отказоустойчивость (99,95%)
- Задержку оповещения не более 5 секунд

**Ключевой вопрос:** Как распределить компоненты системы между фермами (Edge) и головным офисом (Cloud) для обеспечения требований по производительности, надежности и стоимости MVP?

## Решение

### Основное решение: Гибридная Edge-Cloud архитектура

**Концепция:** Вся критическая логика (видеоаналитика, локальное управление, оповещение) размещается на ферме (Edge), а все хранилища данных, аналитика и бизнес-приложения работают в головном офисе (Cloud).

#### Компоненты на ферме (Edge Layer):

1. **Edge-агент** - интеллектуальный модуль, включающий:
   - Video Analytics Service (TensorRT + Python) - локальная видеоаналитика
   - Edge Management Service (Rust/Python) - управление периферией
   - Local Controller (Rust) - контроль кормушек и поилок
   - EMQX (MQTT Broker) - локальный брокер сообщений
   - TimescaleDB - хранение метаданных
   - Redis Edge Cache - локальный кэш
   - Local Storage - архив видеофрагментов

2. **Периферийное оборудование:**
   - IP-камеры (RTSP/ONVIF, включая ночной режим)
   - Кормушки и поилки (Modbus/MQTT)
   - Датчики фильтрации и корма

#### Компоненты в облаке (Cloud Layer):

1. **Ingress:**
   - API Gateway (Kong) - единая точка входа
   - Kafka Cluster - стриминг метрик

2. **Cloud Services:**
   - Aggregation Service (FastAPI) - агрегация данных
   - Analytics Service (FastAPI + Airflow) - аналитика
   - Alerting Service (FastAPI) - оповещения
   - User Management (FastAPI) - управление пользователями
   - Reporting Service (FastAPI) - формирование отчетов

3. **Cloud Storage:**
   - ClickHouse - долгосрочное хранение данных (5+ лет)
   - PostgreSQL - пользователи и фермы
   - MinIO/S3 - архив видео
   - Redis Cloud Cache - кэширование

4. **Authentication:**
   - Keycloak (OAuth2/OIDC) - аутентификация и авторизация

#### Клиентские приложения:
- React Web App - веб-портал
- Flutter Mobile App - мобильное приложение
- ERP/BI Systems - интеграция с внешними системами

## Компромиссы

**Альтернативное решение (выбрано для MVP):**
- ✅ **Плюсы:** 
  - Низкая задержка оповещения (< 5 сек)
  - Работа в офлайн-режиме
  - Отказоустойчивость на уровне фермы
  - Минимальная нагрузка на каналы связи
- ❌ **Минусы:**
  - Более высокая стоимость Edge-оборудования
  - Сложность поддержки распределенной системы
  - Требуется квалифицированный персонал на фермах
- 🎯 **Подходит для:** 
  - Требований к реальному времени
  - Нестабильного интернета
  - Критичных операций

**Основное решение (централизованное):**
- ✅ **Плюсы:**
  - Более низкая стоимость MVP
  - Простота поддержки
  - Централизованное управление
- ❌ **Минусы:**
  - Зависимость от интернета
  - Задержки при передаче данных
  - Невозможность работы офлайн
- 🎯 **Подходит для:**
  - Быстрого запуска MVP
  - Хорошего интернета
  - Некритичных операций

**Стратегия:** Начать с основного решения, обеспечивающего все критические требования (задержка < 5 сек, работа офлайн), затем оптимизировать и масштабировать по мере необходимости.
