# ADR: Архитектура платформы мониторинга скота (Smart Pig Farming)


### <a name="_b7urdng99y53"></a>**Название задачи:**
Проектирование контейнерной архитектуры MVP платформы мониторинга и управления поголовьем скота (Smart Pig Farming)

### <a name="_3bfxc9a45514"></a>**Функциональные требования**

| **№** | **Действующие лица или системы** | **Use Case** | **Описание** |
| :---: | :--- | :--- | :--- |
| UC-01 | Видеокамеры, Нейросеть (партнеры), Оператор | Обнаружение нештатных ситуаций | 1. Камеры передают RTSP поток на Edge-агент<br>2. Нейросеть анализирует кадры в реальном времени (миллисекунды)<br>3. При обнаружении драки, задавливания, болезни или гибели формируется событие<br>4. Событие передается в локальную шину MQTT<br>5. Система оповещений отправляет уведомление оператору (локально) |
| UC-02 | Система оповещений, Оператор | Оповещение о нештатных ситуациях | 1. Система получает событие о нештатной ситуации<br>2. Формируется уведомление (push, SMS, email)<br>3. Уведомление доставляется оператору в течение 5 секунд<br>4. При отсутствии интернета уведомление отправляется локально через WebSocket<br>5. После восстановления связи уведомление дублируется в Cloud |
| UC-03 | Edge-агент, Кормушки/Поилки, Оператор | Управление кормушками и поилками | 1. Оператор устанавливает расписание кормления через интерфейс<br>2. Edge-агент отправляет команды на кормушки (Modbus/MQTT)<br>3. Кормушки выполняют команды (дозировка, время подачи)<br>4. Система мониторит уровень корма и расход в реальном времени<br>5. При снижении уровня формируется событие пополнения запасов |
| UC-04 | Edge-агент, Центральный сервер | Синхронизация данных с центральным сервером | 1. Edge-агент собирает события и телеметрию с датчиков<br>2. Данные сохраняются в локальной БД (TimescaleDB)<br>3. При наличии интернета данные отправляются в Cloud<br>4. Отправка происходит пакетами с задержкой до 10 минут<br>5. При обрыве связи данные буферизируются локально<br>6. После восстановления связи синхронизация продолжается с момента обрыва |
| UC-05 | Система видеоаналитики, Edge-агент | Оценка состояния животных | 1. Камеры ведут непрерывную запись видеопотока<br>2. Нейросеть анализирует внешний вид и поведение животных<br>3. Фиксируются признаки болезней, беспокойства, гибели<br>4. Результаты сохраняются в локальную БД с метками времени<br>5. При обнаружении критических отклонений формируется событие |
| UC-06 | Датчики фильтрации, Edge-агент, Система фильтрации | Мониторинг систем фильтрации воды | 1. Датчики фильтрации передают показатели (давление, качество, температура)<br>2. Edge-агент мониторит состояние систем фильтрации<br>3. При отклонениях от нормы формируется событие<br>4. В случае необходимости отправляется команда на управление клапанами<br>5. Данные синхронизируются с Cloud для анализа |
| UC-07 | Edge-агент, Центральный сервер | Пересчет поголовья | 1. Система агрегирует данные о животных со всех датчиков<br>2. Производится автоматический пересчет поголовья<br>3. Результаты сохраняются в локальной БД<br>4. Данные синхронизируются с Cloud<br>5. При расхождениях формируется уведомление оператору |
| UC-08 | Edge-агент, Датчики кормов | Мониторинг запасов кормов | 1. Датчики уровня корма передают показатели в реальном времени<br>2. Edge-агент анализирует расход и прогнозирует потребность<br>3. Формируются рекомендации по пополнению запасов<br>4. Данные синхронизируются с Cloud<br>5. Информация отображается в интерфейсе оператора |
| UC-09 | Веб-портал, Мобильное приложение, Оператор | Просмотр статуса и управление | 1. Оператор авторизуется через OAuth2/OIDC<br>2. Система проверяет права доступа (RBAC)<br>3. Оператор получает доступ к дашборду с визуализацией<br>4. Отображается состояние животных, кормушек, систем<br>5. Оператор может вручную управлять оборудованием |
| UC-10 | API-шлюз, ERP, BI-системы | Интеграция с внешними системами | 1. Внешняя система отправляет запрос через REST API<br>2. API-шлюз проверяет аутентификацию и права доступа<br>3. Сервис метрик формирует запрошенные данные<br>4. Данные возвращаются в формате JSON/XML<br>5. BI-система получает метрики через ODBC/JDBC |


### <a name="_u8xz25hbrgql"></a>**Нефункциональные требования**

| **№** | **Требование** |
| :---: | :--- |
| NFR-01 | **Доступность:** Центральный сервер должен обеспечивать доступность 99.95% (время простоя не более 4.38 часов в год) |
| NFR-02 | **Производительность (латентность):** Время от момента возникновения нештатной ситуации (зафиксированной видеоаналитикой) до момента оповещения оператора должно составлять не более 5 секунд |
| NFR-03 | **Производительность (видеоаналитика):** Система видеоаналитики должна реагировать в реальном времени с задержкой в миллисекундах |
| NFR-04 | **Работа в офлайн-режиме:** Система должна полностью функционировать при отсутствии интернета. При восстановлении связи синхронизация с центральной системой должна происходить с задержкой не более 10 минут |
| NFR-05 | **Масштабируемость:** Архитектура должна поддерживать неограниченное количество агентов (ферм) без ухудшения производительности системы |
| NFR-06 | **Расширяемость:** Должна быть возможность разработать новый функционал без изменений существующего кода (принцип Open/Closed) |
| NFR-07 | **Гетерогенность:** Система должна поддерживать оборудование разных производителей с различными протоколами (RTSP, ONVIF, Modbus, MQTT) |
| NFR-08 | **Безопасность:** Должно быть реализовано разделение ролей (RBAC) и современные способы аутентификации и авторизации (OAuth2/OIDC) |
| NFR-09 | **Отказоустойчивость Edge:** Локальный агент должен продолжать работу при потере связи с Cloud и при сбоях отдельных компонентов |
| NFR-10 | **Надежность доставки сообщений:** События не должны теряться при передаче (доставка должна быть гарантирована, хотя бы один раз - at-least-once) |
| NFR-11 | **Хранение данных:** Локальное хранение на Edge должно обеспечивать хранение данных за последние 2 недели. В Cloud хранение должно обеспечивать хранение данных за 5+ лет |
| NFR-12 | **API для клиентов:** Система должна иметь API для создания мобильного приложения и веб-приложения |


### <a name="_qmphm5d6rvi3"></a>**Решение**

#### Основное решение (выбрано для MVP): Централизованная архитектура с минимальным Edge

**Концепция:** Максимальная часть логики (видеоаналитика, управление кормлением, оповещения) вынесена в центральное облако, а на фермах размещаются только минимально необходимые компоненты для сбора данных и базового управления.
