**Почему выбрано для MVP:**
- **Низкая стоимость** — не требуется мощное Edge-оборудование (NVIDIA Jetson) на каждой ферме
- **Быстрое внедрение** — разработка и деплой только одного центрального компонента
- **Простота поддержки** — обновление системы в одном месте, без управления распределенными агентами
- **Быстрый вывод на рынок** — можно запустить на 2-3 фермах за 2-3 месяца

**Как работает:**
1. Камеры передают RTSP поток напрямую в облако через интернет
2. Видеоаналитика с нейросетью запускается в облаке (GPU-инстансы)
3. Команды на кормушки/поилки отправляются из облака через интернет (MQTT over WebSocket)
4. При обрыве интернета — базовая работа оборудования сохраняется (локальный контроллер), но видеоаналитика и оповещения недоступны
5. Все данные хранятся централизованно в облаке

**Технологический стек MVP:**

| Компонент | Технология | Обоснование |
|-----------|-----------|-------------|
| **Бэкенд** | Python (FastAPI) + PostgreSQL | Быстрая разработка, единая кодовая база |
| **Видеоаналитика** | Python + GPU (Yandex Cloud/AWS) | Готовая нейросеть от партнеров, мощные GPU в облаке |
| **Брокер** | RabbitMQ / Redis Pub/Sub | Легковесный, простой в настройке |
| **Фронтенд** | React (Web) + Flutter (Mobile) | Кроссплатформенность, быстрая разработка |
| **Хранилище** | PostgreSQL + MinIO (S3) | Все данные в одном месте |
| **Аутентификация** | Keycloak (базовая) | OAuth2/OIDC для безопасности |

**Ограничения MVP:**
- ❌ Зависимость от интернета — при обрыве связи видеоаналитика не работает
- ❌ Единая точка отказа — падение облака останавливает всю систему
- ❌ Высокие затраты на трафик — RTSP видео идет в облако (дорого)
- ❌ Задержка > 5 секунд — зависит от скорости интернета

#### Альтернативное решение (для будущих этапов): Распределенная архитектура с полноценным Edge

**Концепция:** Критичные для быстрого реагирования компоненты (видеоаналитика, управление кормлением, локальные оповещения) размещаются на фермах (Edge), обеспечивая работу офлайн и задержку < 5 секунд. Центр используется для агрегации, аналитики и управления пользователями.

**Когда будет актуально:**
- После успешного MVP и подтверждения бизнес-модели
- При подключении удаленных ферм с плохим интернетом
- При росте числа ферм > 10 (экономия на трафике)
- При необходимости соблюдения жестких SLA (< 5 секунд)

**Ключевые компоненты альтернативного решения:**

| Компонент | Edge (ферма) | Cloud (центр) |
|-----------|--------------|---------------|
| **Видеоаналитика** | ✅ NVIDIA Jetson + TensorRT | ❌ (только агрегация) |
| **Управление кормлением** | ✅ Локальный контроллер (Modbus) | ✅ Управление расписанием |
| **Хранилище** | ✅ TimescaleDB (2 недели) | ✅ ClickHouse (5+ лет) |
| **Оповещения** | ✅ Локальные (WebSocket) | ✅ Глобальные (Push/Email/SMS) |
| **Синхронизация** | ✅ Sync Agent (Rust) | ✅ Kafka Cluster |
| **Брокер** | ✅ EMQX (MQTT) | ✅ Apache Kafka |

**Преимущества альтернативного решения:**
- ✅ **Полная автономность** — работа без интернета (NFR-04)
- ✅ **Распределенная надежность** — отказ одной фермы не влияет на другие
- ✅ **Задержка < 5 секунд** — видеоаналитика на месте (NFR-02)
- ✅ **Экономия трафика** — в облако идут только события, а не видео
- ✅ **Масштабируемость** — неограниченное количество ферм (NFR-05)

**Недостатки альтернативного решения:**
- ❌ **Высокая стоимость** — Edge-оборудование ($2000+ на ферму)
- ❌ **Долгое внедрение** — разработка распределенной системы (6-12 месяцев)
- ❌ **Сложная поддержка** — нужно управлять обновлениями на всех фермах
- ❌ **Сложность отладки** — распределенная система сложнее в диагностике

### **Вывод**

Для MVP выбрано **централизованное решение** как наиболее быстрое и дешевое для проверки бизнес-гипотезы. Это позволяет:
- Запустить систему на 2-3 фермах за 2-3 месяца
- Проверить работу нейросети в реальных условиях
- Собрать обратную связь от операторов
- Подтвердить бизнес-модель перед крупными инвестициями

**План миграции на распределенную архитектуру:**
- **Этап 1 (MVP):** Централизованное решение
- **Этап 2:** Добавление локального кэширования на фермах (буферизация)
- **Этап 3:** Перенос видеоаналитики на Edge (NVIDIA Jetson)
- **Этап 4:** Полная автономность ферм с синхронизацией через Kafka

Такой подход минимизирует риски и позволяет итеративно улучшать систему на основе реального опыта эксплуатации.
